# PostgreSQL EXPLAIN Execution Plan: Query 8 (Dynamic Set Differencing)

## Query
```sql
SELECT 
    curr_u.user_id,
    curr_u.username,
    curr_u.full_name,
    rt.type_code AS current_relationship
FROM snapshot_relationships curr_sr
JOIN users curr_u ON curr_sr.target_user_id = curr_u.user_id
JOIN relationship_types rt ON curr_sr.relationship_type_id = rt.relationship_type_id
WHERE curr_sr.snapshot_id = 'snap_bench_b'
  AND curr_sr.target_user_id NOT IN (
      SELECT prev_sr.target_user_id
      FROM snapshot_relationships prev_sr
      WHERE prev_sr.snapshot_id = 'snap_bench_a'
  )
ORDER BY curr_u.username ASC;
```

## Relational Set-Differencing & Optimization Notes
- **Bloom Filter Subquery Acceleration:** SQLite builds an in-memory Bloom filter for the `NOT IN` subquery over `snap_bench_a`, yielding `O(1)` membership checks for each target user in `snap_bench_b`.
- **Covering Index Scan:** Both subquery and main query read directly from the composite primary key index `(snapshot_id, target_user_id)`.
