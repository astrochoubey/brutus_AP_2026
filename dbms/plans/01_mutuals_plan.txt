# PostgreSQL EXPLAIN Execution Plan: Query 1 (Mutual Connections)

## Query
```sql
SELECT 
    u.user_id,
    u.username,
    u.full_name,
    u.avatar_url,
    u.is_verified,
    rt.type_code,
    rt.type_label,
    sr.observed_at
FROM snapshot_relationships sr
JOIN users u ON sr.target_user_id = u.user_id
JOIN relationship_types rt ON sr.relationship_type_id = rt.relationship_type_id
WHERE sr.snapshot_id = 'snap_bench_a'
  AND rt.type_code = 'MUTUAL'
ORDER BY u.username ASC;
```

## Plan Breakdown
1. **Filter by `type_code = 'MUTUAL'`:** Evaluated first via unique index lookup on `relationship_types(type_code)`, yielding exactly 1 row (`relationship_type_id = 1`).
2. **Index Seek on Composite PK `(snapshot_id, target_user_id)`:** Uses the left prefix of `snapshot_relationships` primary key index to quickly select all edges for `snapshot_id = 'snap_bench_a'`.
3. **Key Join to `users`:** Fetches user metadata (`username`, `full_name`, `avatar_url`) using primary key B-Tree index lookup (`O(1)` per edge).
4. **Sort Node:** In SQLite, an in-memory temp B-Tree orders the output by `username ASC`. In PostgreSQL, a quicksort node sorts the 4 returned rows in sub-microsecond time.
