# PostgreSQL EXPLAIN Execution Plan: Query 5 (Network Growth Time Series)

## Query
```sql
SELECT 
    s.snapshot_id,
    s.scan_id,
    s.total_followers,
    s.total_following,
    s.total_mutuals,
    ROUND(sm.reciprocity_ratio, 4) AS reciprocity_ratio,
    ROUND(sm.turnover_rate, 4) AS turnover_rate,
    ROUND(sm.network_density, 4) AS network_density,
    s.created_at AS snapshot_timestamp
FROM snapshots s
JOIN snapshot_metrics sm ON s.snapshot_id = sm.snapshot_id
WHERE s.observer_id = 'obs_default'
ORDER BY s.created_at ASC;
```

## Performance & Design Justification
- `idx_snapshots_observer` eliminates sequential scans over the entire `snapshots` table.
- Direct 1-to-1 join with `snapshot_metrics` via unique index lookup ensures rapid data retrieval for frontend dashboard trendlines.
